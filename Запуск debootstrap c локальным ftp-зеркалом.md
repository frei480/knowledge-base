# Правильный Запуск Debootstrap В Astra Linux С Локальным FTP-зеркалом

Для правильного запуска `debootstrap` в операционной системе Astra Linux с использованием локального зеркала репозитория на FTP-сервере необходимо выполнить несколько ключевых шагов. Этот процесс позволяет создать базовую систему Astra Linux в указанном каталоге, используя пакеты с вашего внутреннего сервера, что значительно ускоряет установку и не требует подключения к внешнему Интернету.

## Шаг 1: Подготовка Окружения

Перед запуском `debootstrap` убедитесь, что все необходимые инструменты установлены в вашей основной системе Astra Linux.

1. Установка debootstrap:

Если утилита еще не установлена, установите ее из репозитория:

Bash

```
sudo apt update
sudo apt install debootstrap
```

2. Доступность FTP-сервера:

Убедитесь, что с машины, где вы запускаете debootstrap, есть сетевой доступ к вашему FTP-серверу. Проверить это можно, например, с помощью утилиты ping или curl:

Bash

```
ping ftp.your.local.domain
# или по IP-адресу
ping 192.168.1.10
```

где `192.168.1.10` — IP-адрес вашего FTP-сервера.

## Шаг 2: Структура Зеркала На FTP-сервере

Ключевым моментом для успешной работы `debootstrap` является правильная структура каталогов на вашем FTP-сервере. `debootstrap` ожидает найти файлы `Release`, `Release.gpg` и другие метаданные репозитория по определенному пути.

Структура на вашем FTP-сервере должна выглядеть примерно так:

```
ftp://192.168.1.10/astra/
└── dists/
    └── smolensk/
        ├── InRelease
        ├── Release
        ├── Release.gpg
        ├── main/
        │   └── binary-amd64/
        │       ├── Packages
        │       ├── Packages.gz
        │       └── ...
        └── ...
```

Важно, чтобы путь, который вы будете указывать в команде, вёл к каталогу, содержащему подкаталог `dists`.

## Шаг 3: Выполнение Команды Debootstrap

Основная команда для запуска `debootstrap` будет выглядеть следующим образом. Обратите внимание на использование опции `--no-check-gpg`, если вы не импортировали ключи репозитория Astra Linux в свою систему.

**Синтаксис команды:**

Bash

```
sudo debootstrap --arch=<архитектура> [--no-check-gpg] <кодовое_имя_релиза> <каталог_установки> ftp://<ip_или_имя_сервера>/<путь_к_зеркалу>
```

**Пример команды:**

Предположим, у вас следующие параметры:

- **Архитектура:** `amd64`
    
- **Кодовое имя релиза Astra Linux:** `smolensk` (для Astra Linux Special Edition 1.6)
    
- **Каталог для установки базовой системы:** `/mnt/new_astra`
    
- **Адрес FTP-сервера:** `192.168.1.10`
    
- **Путь к корню зеркала на FTP:** `/pub/astra/`
    

Команда будет выглядеть так:

Bash

```
sudo debootstrap --arch=amd64 --no-check-gpg smolensk /mnt/new_astra ftp://192.168.1.10/pub/astra/
```

**Разбор параметров:**

- `--arch=amd64`: Указывает архитектуру создаваемой системы. Для большинства современных компьютеров это будет `amd64`.
    
- `--no-check-gpg`: **(Рекомендуется для локальных зеркал)** Отключает проверку GPG-подписей файлов репозитория. Это часто необходимо при работе с локальными или неофициальными зеркалами, где управление ключами может быть затруднено. Если вы уверены в целостности вашего зеркала и ключи установлены в системе, этот параметр можно опустить.
    
- `smolensk`: Кодовое имя релиза Astra Linux. Используйте актуальное для вашей версии (например, `orel` для Astra Linux Common Edition).
    
- `/mnt/new_astra`: Каталог на вашем хост-компьютере, в который будет установлена базовая система. Этот каталог должен быть пустым.
    
- `ftp://192.168.1.10/pub/astra/`: URL вашего локального зеркала. `debootstrap` автоматически добавит к этому пути необходимые подкаталоги, такие как `dists/smolensk`.
    

## Шаг 4: Дальнейшие Действия

После успешного выполнения команды `debootstrap` в каталоге `/mnt/new_astra` будет создана минимальная, но работоспособная файловая система Astra Linux. Вы можете войти в эту систему с помощью `chroot` для дальнейшей настройки:

Bash

```
sudo chroot /mnt/new_astra
```

Внутри `chroot`-окружения вы сможете устанавливать дополнительные пакеты, настраивать сеть, создавать пользователей и выполнять другие административные задачи.

## Возможные Проблемы И Их Решения

- **Ошибка "Couldn't find 'Release' file":** Проверьте правильность URL вашего зеркала. Убедитесь, что указанный путь ведет к директории, которая содержит подкаталог `dists`.
    
- **Ошибка GPG verification failed:** Используйте флаг `--no-check-gpg` или убедитесь, что GPG-ключи репозитория Astra Linux установлены и доверены в вашей основной системе.
    
- **Сетевые ошибки:** Проверьте доступность FTP-сервера, настройки брандмауэра и правильность сетевых настроек на обеих машинах.
