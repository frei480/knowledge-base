Особенности применения ранжирующих функций, таких как `ROW_NUMBER()`, `RANK()`, `DENSE_RANK()`, `NTILE()` и других, совместно с оператором `CASE` в SQL-запросах. Это очень мощная комбинация, которая позволяет создавать сложные логики нумерации и группировки данных.

# Общие Принципы Применения Ранжирующих Функций

Прежде всего, напомним, как работают ранжирующие функции:

- **`ROW_NUMBER()`**: Присваивает уникальный последовательный номер каждой строке в рамках указанной партиции. Если порядок одинаковый, номера будут присвоены произвольно, но последовательно.
- **`RANK()`**: Присваивает ранг каждой строке в рамках партиции. Если несколько строк имеют одинаковые значения для ранжирования, им присваивается один и тот же ранг, и следующий ранг будет пропущен (например, 1, 2, 2, 4).
- **`DENSE_RANK()`**: Аналогично `RANK()`, но не пропускает ранги. Если несколько строк имеют одинаковые значения, им присваивается один и тот же ранг, и следующий ранг будет последовательным (например, 1, 2, 2, 3).
- **`NTILE(n)`**: Делит строки в партиции на `n` групп (плиток) и присваивает номер группы каждой строке.
- **`LAG()` / `LEAD()`**: Позволяют получить значение из предыдущей/следующей строки в рамках партиции.
- **`FIRST_VALUE()` / `LAST_VALUE()`**: Возвращают первое/последнее значение в рамках партиции.

Все эти функции требуют предложения `OVER()`, которое определяет:

- **`PARTITION BY`**: Позволяет разделить результирующий набор строк на разделы, к которым применяется функция. Если `PARTITION BY` отсутствует, вся таблица рассматривается как один раздел.
- **`ORDER BY`**: Определяет порядок строк в каждом разделе, по которому происходит ранжирование.

# Сочетание Ранжирующих Функций С Оператором `CASE`

Оператор `CASE` позволяет выполнять условную логику в SQL. Его синтаксис:
```sql
CASE
    WHEN условие1 THEN результат1
    WHEN условие2 THEN результат2
    ...
    ELSE результат_по_умолчанию
END
```

Когда `CASE` комбинируется с ранжирующими функциями, открываются следующие возможности:

1. Условное ранжирование/нумерация:

    Вы можете применять CASE внутри ORDER BY или PARTITION BY ранжирующей функции, чтобы динамически менять критерии ранжирования.
    
    - **Пример:** Ранжирование студентов по оценкам, но для студентов из определенного факультета использовать другой критерий.



    SQL

    ```
    SELECT
        StudentName,
        Faculty,
        Score,
        ROW_NUMBER() OVER (
            PARTITION BY Faculty
            ORDER BY
                CASE
                    WHEN Faculty = 'Computer Science' THEN Score DESC
                    ELSE Score ASC
                END
        ) AS FacultyRank
    FROM Students;
    ```

    В этом примере, для факультета 'Computer Science' студенты будут ранжироваться по убыванию балла, а для других факультетов - по возрастанию.
    
2. Фильтрация на основе ранга:

    Вы можете использовать CASE для создания флагов или категорий на основе присвоенного ранга, а затем фильтровать по ним.
    
    - **Пример:** Выделить топ-3 продукта по продажам в каждой категории.
    
    <!-- end list -->

    SQL

    ```
    SELECT
        ProductName,
        Category,
        Sales,
        ProductRank,
        CASE
            WHEN ProductRank <= 3 THEN 'Top 3'
            ELSE 'Other'
        END AS RankCategory
    FROM (
        SELECT
            ProductName,
            Category,
            Sales,
            ROW_NUMBER() OVER (PARTITION BY Category ORDER BY Sales DESC) AS ProductRank
        FROM Products
    ) AS RankedProducts
    WHERE
        CASE
            WHEN ProductRank <= 3 THEN 1
            ELSE 0
        END = 1; -- или WHERE ProductRank <= 3, но CASE показывает пример использования
    ```

    Хотя в данном простом случае `WHERE ProductRank <= 3` было бы эффективнее, `CASE` полезен, когда логика фильтрации сложнее и требует нескольких условий, зависящих от ранга.
    
3. Условное применение разных ранжирующих функций:

    Хотя напрямую CASE не может выбирать какую ранжирующую функцию применять (например, ROW_NUMBER() или DENSE_RANK()), вы можете использовать его для создания флагов, на основе которых затем в другом шаге запроса будет применена нужная функция, или для выбора нужного результата из нескольких предварительно рассчитанных ранков.
    
    - **Пример (несколько ранков и выбор одного по условию):**
    
    <!-- end list -->

    SQL

    ```
    SELECT
        OrderId,
        OrderDate,
        TotalAmount,
        ROW_NUMBER() OVER (PARTITION BY OrderDate ORDER BY TotalAmount DESC) AS RowNumRank,
        DENSE_RANK() OVER (PARTITION BY OrderDate ORDER BY TotalAmount DESC) AS DenseRank,
        CASE
            WHEN TotalAmount > 1000 THEN RowNumRank
            ELSE DenseRank
        END AS ChosenRank
    FROM Orders;
    ```

    Здесь мы вычисляем оба ранга, а затем выбираем нужный в зависимости от условия.
    
4. Создание динамических партиций или порядков:

    CASE может использоваться внутри PARTITION BY или ORDER BY для динамического изменения групп или порядка, по которым происходит ранжирование.
    
    - **Пример:** Ранжирование сотрудников по зарплате, но для менеджеров и обычных сотрудников использовать разные группы или порядки.
    
    <!-- end list -->

    SQL

    ```
    SELECT
        EmployeeName,
        Department,
        JobTitle,
        Salary,
        ROW_NUMBER() OVER (
            PARTITION BY
                CASE
                    WHEN JobTitle = 'Manager' THEN 'Managers'
                    ELSE Department
                END
            ORDER BY Salary DESC
        ) AS EmployeeRank
    FROM Employees;
    ```

    В этом случае, менеджеры будут ранжироваться в одной общей группе 'Managers', а остальные сотрудники - в пределах своих департаментов.
    
5. Обработка "дыр" или особых условий:

    Вы можете использовать CASE для обработки особых случаев, которые влияют на ранжирование. Например, игнорировать определенные записи при ранжировании или присваивать им специальные ранги.
    
    - **Пример:** Если статус заказа "Cancelled", не ранжировать его, или присвоить ему ранг 0.
    
    <!-- end list -->

    SQL

    ```
    SELECT
        OrderId,
        OrderStatus,
        OrderDate,
        ROW_NUMBER() OVER (
            PARTITION BY OrderDate
            ORDER BY
                CASE
                    WHEN OrderStatus = 'Cancelled' THEN 999999 -- Отбрасываем в конец
                    ELSE OrderId -- Или любой другой критерий для не-отмененных
                END
        ) AS OrderRank
    FROM Orders;
    ```
    

# Ключевые Соображения И Рекомендации:

- **Производительность:** Использование `CASE` внутри `OVER()` может немного усложнить оптимизатору запрос. В большинстве случаев это не критично, но для очень больших таблиц и сложных условий стоит провести тестирование производительности.
- **Читаемость кода:** Слишком много вложенных `CASE` или сложных условий могут сделать запрос трудночитаемым. Старайтесь структурировать запрос с помощью CTE (Common Table Expressions) или подзапросов, чтобы разбить логику на более мелкие, понятные шаги.
- **Индексы:** Для эффективной работы ранжирующих функций (особенно с `PARTITION BY` и `ORDER BY`) убедитесь, что соответствующие столбцы проиндексированы.
- **Логика:** Тщательно продумайте, как `CASE` будет влиять на порядок и группировку. Ошибка в условиях `CASE` может привести к некорректным результатам ранжирования.
- **Альтернативы:** Иногда вместо `CASE` для условной логики внутри `OVER()` можно использовать агрегатные функции с `FILTER` (если ваш SQL-диалект это поддерживает), или просто создать несколько CTE/подзапросов и объединить их. Однако `CASE` является наиболее универсальным и широко поддерживаемым способом.

# Пример Сложного Использования:

Допустим, у нас есть таблица продаж, и мы хотим:

1. Для каждого региона, определить топ-5 продуктов по объему продаж за каждый месяц.
2. Но для региона 'East' учитывать только продукты, у которых `ProfitMargin` выше 0.15.

<!-- end list -->

SQL

```
WITH MonthlySales AS (
    SELECT
        Region,
        ProductName,
        DATE_TRUNC('month', SaleDate) AS SalesMonth,
        SUM(SaleAmount) AS TotalSales,
        AVG(ProfitMargin) AS AvgProfitMargin -- Предположим, ProfitMargin есть в таблице продаж
    FROM Sales
    GROUP BY
        Region,
        ProductName,
        DATE_TRUNC('month', SaleDate)
)
SELECT
    Region,
    ProductName,
    SalesMonth,
    TotalSales,
    RankBySales
FROM (
    SELECT
        Region,
        ProductName,
        SalesMonth,
        TotalSales,
        AvgProfitMargin,
        ROW_NUMBER() OVER (
            PARTITION BY
                Region,
                SalesMonth
            ORDER BY
                CASE
                    WHEN Region = 'East' AND AvgProfitMargin <= 0.15 THEN 0 -- Отбрасываем такие продукты в самый низ
                    ELSE TotalSales
                END DESC -- Ранжируем по убыванию продаж
        ) AS RankBySales
    FROM MonthlySales
) AS RankedSales
WHERE
    RankBySales <= 5
    AND CASE WHEN Region = 'East' AND AvgProfitMargin <= 0.15 THEN 0 ELSE 1 END = 1; -- Убедимся, что отброшенные не попали в топ
```

В этом примере:

- Мы сначала агрегируем данные по месяцам, регионам и продуктам.
- Затем внутри подзапроса `RankedSales` мы используем `ROW_NUMBER()` с `CASE` в `ORDER BY`. Для региона 'East', если `AvgProfitMargin` меньше или равен 0.15, мы фактически присваиваем этому продукту очень низкое значение для сортировки (чтобы он оказался в конце списка), иначе используем `TotalSales`.
- Наконец, мы фильтруем результат, чтобы получить только топ-5 и исключить те продукты из региона 'East', которые не соответствовали критерию маржи.

Таким образом, комбинация ранжирующих функций и оператора `CASE` предоставляет огромную гибкость для решения сложных аналитических задач в SQL, позволяя реализовать условную логику прямо в процессе ранжирования данных.
