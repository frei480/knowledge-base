В MS SQL Server нельзя создать параметрическое представление (VIEW) напрямую** с помощью стандартного синтаксиса `CREATE VIEW`. Представления по своей сути являются "виртуальными таблицами" и не принимают параметры при вызове, так же как и обычные таблицы.

Однако, для решения вашей задачи существуют стандартные и гораздо более мощные альтернативы. Самым правильным и эффективным способом является использование **встраиваемых табличных функций (Inline Table-Valued Functions, iTVF)**.

### Решение: Встраиваемые табличные функции (iTVF)

Это именно тот инструмент, который ведет себя как параметрическое представление. Он принимает параметры и возвращает результат в виде таблицы, которую можно использовать в запросах так же, как обычную таблицу или представление.

**Ключевое преимущество iTVF для производительности:** В отличие от других типов функций, оптимизатор запросов SQL Server "видит" внутренний код iTVF и может встроить его логику непосредственно в общий план запроса. Это означает, что условие `WHERE` внутри функции будет применено на самом раннем этапе, точно так же, как если бы вы написали его в основном запросе. В результате получается очень эффективный план выполнения.

#### Пример

Допустим, у вас есть представление, которое возвращает заказы:

SQL

```
CREATE VIEW dbo.v_AllOrders
AS
SELECT
    o.OrderID,
    o.OrderDate,
    c.CustomerName,
    p.ProductName,
    oi.Quantity,
    oi.Price
FROM Orders AS o
JOIN Customers AS c ON o.CustomerID = c.CustomerID
JOIN OrderItems AS oi ON o.OrderID = oi.OrderID
JOIN Products AS p ON oi.ProductID = p.ProductID;
GO
```

Если вы напишете `SELECT * FROM dbo.v_AllOrders WHERE CustomerID = 5`, оптимизатор, конечно, "протолкнет" условие внутрь, но сама концепция представления не подразумевает параметра.

Теперь создадим параметрическую альтернативу с помощью iTVF для получения заказов конкретного клиента:

SQL

```
-- Создание встраиваемой табличной функции
CREATE FUNCTION dbo.f_GetOrdersByCustomer (@CustomerID INT)
RETURNS TABLE
AS
RETURN
(
    -- Тело функции - это всего один SELECT-запрос
    SELECT
        o.OrderID,
        o.OrderDate,
        c.CustomerName,
        p.ProductName,
        oi.Quantity,
        oi.Price
    FROM Orders AS o
    JOIN Customers AS c ON o.CustomerID = c.CustomerID
    JOIN OrderItems AS oi ON o.OrderID = oi.OrderID
    JOIN Products AS p ON oi.ProductID = p.ProductID
    WHERE o.CustomerID = @CustomerID -- Вот наш параметр!
);
GO
```

#### Как использовать iTVF

Использовать эту функцию так же просто, как и представление, но теперь вы передаете параметр:

SQL

```
-- Получить все заказы для клиента с ID = 10
SELECT * FROM dbo.f_GetOrdersByCustomer(10);

-- Можно соединять (JOIN) с другими таблицами
SELECT
    u.UserName,
    ord.*
FROM dbo.f_GetOrdersByCustomer(25) AS ord
JOIN Users AS u ON ord.ManagerID = u.UserID
WHERE ord.OrderDate > '2025-01-01';
```

План выполнения для последнего запроса будет оптимальным, так как SQL Server с самого начала будет работать только с заказами клиента с ID = 25.

### Другие, менее предпочтительные, альтернативы

1. **Многооператорные табличные функции (Multi-Statement Table-Valued Functions, MSTVF):** Позволяют выполнять более сложную логику (циклы, временные таблицы), но имеют **существенный недостаток в производительности**. Оптимизатор плохо оценивает количество строк, которое вернет такая функция (часто предполагает, что вернется 1 или 100 строк), что приводит к неэффективным планам запросов. Их следует избегать, если можно обойтись iTVF.
    
2. **Хранимые процедуры:** Могут принимать параметры и возвращать наборы данных.
    
    - **Плюс:** Очень гибкие, могут изменять данные.
        
    - **Минус:** Результат хранимой процедуры нельзя напрямую использовать в `SELECT` или `JOIN` с другими таблицами. Для этого нужно сначала поместить результат во временную таблицу (`#temp_table`) или табличную переменную (`@table_variable`), что усложняет код.
        

### Сводка и рекомендация

|Инструмент|Поддерживает параметры?|Можно использовать в `FROM`/`JOIN`?|Производительность|Рекомендация|
|---|---|---|---|---|
|**Представление (VIEW)**|Нет|Да|Хорошая, но без параметров|Для инкапсуляции простых запросов без параметров.|
|**iTVF (Inline)**|**Да**|**Да**|**Отличная**|**Идеальная замена параметрическому представлению.**|
|**MSTVF (Multi-statement)**|Да|Да|Потенциально плохая|Только для сложной логики, которую нельзя выразить одним запросом.|
|**Хранимая процедура**|Да|Нет (напрямую)|Хорошая|Для выполнения действий, возврата нескольких наборов данных, сложной логики.|

**Вывод:** Для вашей задачи — ускорения работы представления за счет параметрической фильтрации `WHERE` — **наилучшим и самым правильным решением является встраиваемая табличная функция (Inline Table-Valued Function)**. Она обеспечивает и удобство использования, и максимальную производительность.
