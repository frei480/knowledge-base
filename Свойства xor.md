# 1. Самое Важное Свойство (00:00)

Фундаментальное свойство XOR, на котором строятся все приведенные ниже примеры:
$$a \oplus b \oplus b = a$$

Если применить одну и ту же маску (значение) к числу дважды, мы вернемся к исходному значению. Это происходит потому, что:
1. $b \oplus b = 0$ (любое число XOR само себя дает ноль).
2. $a \oplus 0 = a$ (XOR с нулем не изменяет число).

# 2. Шифрование (Encryption) (00:49)

Благодаря свойству обратимости, XOR является простейшим алгоритмом симметричного шифрования.

**Пример на Python:**
```python
def encrypt(m, k):
    # m - сообщение (строка), k - ключ (целое число)
    return ''.join([chr(ord(a) ^ k) for a in m])

msg = "hello, world"
key = 69

cipher = encrypt(msg, key)    # Зашифровать
decrypted = encrypt(cipher, key) # Расшифровать тем же ключом
```
*   **Как это работает:** Мы превращаем символ в число (`ord`), применяем XOR с ключом, а затем возвращаем в символ (`chr`). Повторное применение XOR с тем же ключом возвращает исходный текст.
*   **Важно:** Tsoding отмечает, что это «игрушечное» шифрование, уязвимое для частотного анализа, и его нельзя использовать в реальных проектах.

# 3. Обмен Значений Переменных (Swapping Variables) (02:03)

Классическая задача: поменять местами значения `a` и `b` без использования третьей временной переменной.

**Реализация на C:**
```c
int a = 69;
int b = 420;

a = a ^ b; // a теперь хранит "составное" состояние
b = b ^ a; // b = b ^ (a ^ b) => b = a
a = a ^ b; // a = (a ^ b) ^ a => a = b
```
В современных языках (как Python) это не актуально (там есть `a, b = b, a`), а современные компиляторы C и так оптимизируют обычный обмен через `temp`. Tsoding называет это «трюком для вечеринок» (party trick).

# 4. Поиск Дубликата (Duplicate Elements) (05:21)

Это популярная (и, по мнению автора, плохая) задача с собеседований.
**Условие:** Есть массив чисел от 1 до 100, где все числа встречаются по одному разу, кроме одного, которое дублируется. Нужно найти его максимально эффективно.

**Алгоритм:**
1. Берем переменную `x = 0`.
2. Проходим XOR-ом по всем числам от 1 до 100 (эталонная последовательность).
3. Проходим XOR-ом по всем элементам нашего массива.
4. В итоге все числа, встретившиеся дважды (один раз в эталоне и один раз в массиве), сократятся в 0. Число, которое было в массиве дважды (а в эталоне один раз), встретится всего 3 раза ($a \oplus a \oplus a = a$) и останется в переменной `x`.

**Код из Gist (C):**
```c
int x = 0;
for (int i = 1; i <= 100; ++i) x ^= i;       // XOR эталона
for (int i = 0; i < size; ++i) x ^= xs[i];   // XOR массива с дубликатом
printf("Duplicate is: %d\n", x);
```

# 5. XOR Связный Список (XOR Linked List) (08:51)

Это самая сложная и интересная часть. В обычном двусвязном списке каждый узел хранит два указателя: `prev` и `next`. XOR-список позволяет хранить **оба указателя в одном поле**, экономя память.

**Концепция:**
Вместо `prev` и `next` мы храним `n->xored = prev ^ next`.

**Как перемещаться по такому списку:**
Чтобы получить адрес следующего узла (`next`), нам нужно знать адрес предыдущего (`prev`):
$$next = n \to xored \oplus prev$$
Это работает, так как $(prev \oplus next) \oplus prev = next$.

**Реализация (из Gist):**
1.  **Структура узла:**
    ```c
    typedef struct Node {
        int value;
        uintptr_t xored; // Здесь хранится адрес (prev ^ next)
    } Node;
    ```
2.  **Добавление элемента (`ll_append`):**
    При добавлении нового узла в конец, мы обновляем `xored` у текущего хвоста, добавляя туда адрес нового узла через XOR, и устанавливаем `xored` нового узла равным адресу старого хвоста.
3.  **Итерация:**
    ```c
    uintptr_t prev = 0; // Для первого узла prev - это NULL
    Node *curr = list.begin;
    while (curr != NULL) {
        printf("%d\n", curr->value);
        Node *next = (Node *)(curr->xored ^ prev); // Вычисляем следующий адрес
        prev = (uintptr_t)curr; // Текущий становится предыдущим
        curr = next;            // Переходим вперед
    }
    ```

**Удивительный эффект:** Если начать итерацию с `list.end`, список автоматически будет читаться в обратном порядке без изменения логики функции — направление зависит только от того, с какой стороны вы «зашли».

# Итог (17:24)
Все эти возможности — шифрование, обмен без `temp`, поиск дубликатов и компактные списки — являются следствием одного математического свойства. Tsoding подчеркивает, что хотя многие из этих вещей редко применяются в промышленном коде, понимание XOR критически важно для системного программиста.
