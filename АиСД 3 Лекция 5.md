# Лекция 5: Суффиксный Автомат: Структура И Алгоритм Построения

## 1. Теоретическая База И Свойства

### Классы Эквивалентности И Longest
Все подстроки строки $S$ разбиваются на классы эквивалентности (по множеству позиций окончания вхождений — `endpos`).
Структура классов однозначно определяется множеством **самых длинных строк** («лонгестов») в каждом классе.

**Критерий «лонгеста»:**
Строка $u$ является самой длинной в своем классе эквивалентности тогда и только тогда, когда выполнено одно из двух условий:
1. $u$ — префикс всей строки $S$.
2. Строку $u$ можно продолжить влево двумя **разными** символами, оставаясь подстрокой $S$ (т.е. $\exists a, b \in \Sigma, a \neq b$, такие что $au$ и $bu$ — подстроки $S$).

*Интуиция:* Если слева всегда стоит только один и тот же символ, то множество вхождений $u$ совпадает с множеством вхождений $xu$, и они лежат в одном классе. Если символы разные или это префикс — множества вхождений разделяются.

### Суффиксные Ссылки
Для каждого класса $C$ определена **суффиксная ссылка** (`link`).
*   Если последовательно отбрасывать первый символ от самой длинной строки класса ($len(C)$), мы остаемся в том же классе, пока не попадем в строку длины, меньшей минимальной в этом классе.
*   `link(C)` ведет в класс, содержащий самый длинный суффикс строки из $C$, который лежит в **другом** классе эквивалентности.
*   Дерево суффиксных ссылок по сути представляет собой дерево суффиксов (в сжатом виде).

### Терминальные Состояния
Вершины автомата должны быть помечены как терминальные, если они соответствуют суффиксам строки $S$.
*   В процессе построения за терминальностью следить не обязательно.
*   В конце построения терминальные вершины восстанавливаются так: берем состояние, соответствующее всей строке, и проходим по суффиксным ссылкам до корня. Все посещенные вершины — терминальные.

## 2. Алгоритм Построения

Алгоритм **инкрементальный** (on-line): мы добавляем символы строки $S$ по одному и перестраиваем автомат.
Пусть построен автомат для строки $S$, добавляем символ $c$.

### Изменение «лонгестов»
При добавлении символа $c$:
1.  Никакая старая строка, бывшая «лонгестом», не перестает им быть.
2.  Гарантированно появляется один новый «лонгест» — вся новая строка $Sc$.
3.  Может появиться еще **максимум один** новый «лонгест» (это происходит при расщеплении старого класса). Это будет $s_0$ — самый длинный суффикс новой строки $Sc$, который уже встречался в $S$ раньше.

*Следствие:* Количество состояний в суффиксном автомате линейно (не более $2|S|$).

### Процесс Добавления Символа $c$
Пусть `last` — состояние, соответствующее всей текущей строке $S$.
Создаем новое состояние `cur`, соответствующее $Sc$.
`len(cur) = len(last) + 1`.

Мы идем по суффиксным ссылкам от `last` к корню, пытаясь найти переход по символу $c$. Пусть текущая вершина в цикле — `p`.

#### Случай 1: Переходов По $c$ Вообще Нет (символ Новый Для Рассматриваемых суффиксов)
Пока мы идем по ссылкам от `last` и не видим перехода по $c$, мы создаем переходы из рассматриваемых вершин `p` в новое состояние `cur`.
*   Если дошли до корня и не нашли перехода: `link(cur) = root`.
*   Это означает, что $c$ — абсолютно новый символ в этом контексте.

#### Случай 2: Переход По $c$ Найден, И Он «хороший»
Пусть мы нашли первую вершину `p`, из которой уже есть переход по $c$ в вершину `q`.
Проверяем условие длины: `len(q) == len(p) + 1`.
*   Это значит, что $q$ соответствует «лонгесту», который получается дописыванием $c$ к $p$. Класс расщеплять не нужно.
*   Действие: `link(cur) = q`.
*   На этом обработка заканчивается.

#### Случай 3: Переход Найден, Но Он «плохой» (Расщепление / Клонирование)
Нашли `p` с переходом в `q` по $c$, но `len(q) > len(p) + 1`.
*   Это значит, что состояние `q` содержит не только строку $p + c$, но и какие-то более длинные строки. Теперь, при добавлении нового вхождения $p + c$ (как суффикса текущей строки), класс `q` должен разделиться:
    *   Старые длинные строки остаются со старым `endpos`.
    *   Строка $p + c$ (и более короткие из $q$) получает новое вхождение.

**Действие (Клонирование):**
1.  Создаем состояние `clone` — копию `q`.
    *   `len(clone) = len(p) + 1` (важно!).
    *   Все переходы (next) из `clone` копируются из `q`.
    *   `link(clone) = link(q)`.
2.  Обновляем ссылки:
    *   `link(q) = clone` (старый класс теперь ссылается на отщепленную часть).
    *   `link(cur) = clone`.
3.  Перенаправление переходов:
    *   Идем от `p` по суффиксным ссылкам вверх. Пока переходы из этих вершин по символу $c$ ведут в `q`, перенаправляем их в `clone`.

## 3. Итоговый Псевдокод

Переменные:
*   `st` — массив состояний (len, link, next).
*   `last` — индекс состояния всей строки (изначально 0/root).
*   `sz` — счетчик состояний (изначально 1).

Функция `extend(c)`:
1.  `cur = sz++`.
2.  `st[cur].len = st[last].len + 1`.
3.  `p = last`.
4.  Пока `p != -1` и нет перехода `st[p].next[c]`:
    *   `st[p].next[c] = cur`.
    *   `p = st[p].link`.
5.  Если `p == -1`:
    *   `st[cur].link = 0` (корень).
6.  Иначе:
    *   `q = st[p].next[c]`.
    *   Если `st[p].len + 1 == st[q].len`:
        *   `st[cur].link = q`.
    *   Иначе (клонирование):
        *   `clone = sz++`.
        *   `st[clone].len = st[p].len + 1`.
        *   `st[clone].next = st[q].next` (копируем переходы).
        *   `st[clone].link = st[q].link`.
        *   `st[q].link = clone`.
        *   `st[cur].link = clone`.
        *   Пока `p != -1` и `st[p].next[c] == q`:
            *   `st[p].next[c] = clone`.
            *   `p = st[p].link`.
7.  `last = cur`.

## 4. Замечания По Сложности
*   Количество состояний: не более $2|S|$.
*   Количество переходов: не более $3|S|$.
*   Амортизированное время построения: $O(|S| \cdot |\Sigma|)$. Все циклы (по ссылкам и перенаправление ребер) суммарно работают за линейное время (доказательство через потенциалы или анализ изменения длин).
