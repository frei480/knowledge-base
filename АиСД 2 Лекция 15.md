# Лекция 15: Центроиды И Heavy-Light Декомпозиция (HLD)

## 1. Поиск Центроида

### Определение
**Центроид дерева** — это вершина $V$, после удаления которой размер любой из оставшихся компонент связности не превышает $N/2$ (где $N$ — число вершин в дереве).

### Свойства
*   В любом дереве всегда существует центроид.
*   Центроидов может быть один или два. Если их два, они обязательно соединены ребром.

### Алгоритм Поиска
1.  Подвешиваем дерево за произвольный корень (например, вершину 0).
2.  Для каждой вершины $V$ считаем размер её поддерева $S(V)$.
3.  Начинаем с корня. Спускаемся в ребенка, если размер его поддерева $\ge N/2$.
4.  Повторяем спуск, пока есть такой ребенок.
5.  Вершина, в которой мы остановились (у которой все дети имеют размер $< N/2$), является центроидом.
    *   *Доказательство корректности:* При удалении такой вершины все дети образуют компоненты $< N/2$. Оставшаяся часть дерева «сверху» имеет размер $N - S(V) \le N - N/2 = N/2$.

## 2. Центроидная Декомпозиция

Это метод решения задач (часто на подсчет путей или других объектов) с использованием принципа «Разделяй и властвуй».

### Алгоритм
1.  Находим центроид $C$ текущего дерева.
2.  Решаем задачу для всех путей/объектов, которые **проходят через** $C$.
3.  Удаляем $C$ из дерева.
4.  Рекурсивно запускаем алгоритм для всех образовавшихся компонент связности (поддеревьев).

**Асимптотика:** $O(N \log N)$.
*   На каждом уровне рекурсии мы обрабатываем дерево за $O(N)$.
*   Глубина рекурсии — $O(\log N)$, так как на каждом шаге размер компонент уменьшается как минимум вдвое.

### Пример Задачи №1: Количество Путей Длины $D$
Нужно найти число пар вершин $(u, v)$, расстояние между которыми равно $D$.

**Решение через декомпозицию:**
1.  На уровне центроида $C$ считаем пути, проходящие через $C$.
2.  Запускаем DFS/BFS из $C$, считаем глубины всех вершин в текущем поддереве.
3.  Нам нужны пары с глубинами $h_1 + h_2 = D$.
4.  Используем массив подсчета (frequency array) глубин.
5.  **Важно:** Нужно исключить случаи, когда обе вершины $u$ и $v$ находятся в одном и том же поддереве потомка $C$ (такой путь не проходит через $C$, а «загибается» внутри поддерева).
    *   *Метод:* Считаем ответ для всех вершин глобально, затем вычитаем ответы, посчитанные внутри каждого поддерева потомка отдельно (для тех же глубин).
6.  Суммируем результаты рекурсивных вызовов.

### Пример Задачи №2: Количество Троек Вершин На Попарном Расстоянии $D$
Нужны тройки $(u, v, w)$, где $dist(u,v) = dist(v,w) = dist(u,w) = D$.

**Анализ:**
Такая конфигурация возможна, только если существует центральная вершина $A$ («хаб»), от которой до $u, v, w$ расстояние равно $D/2$. Следовательно, $D$ должно быть четным. Вершины должны лежать в разных ветках относительно $A$.

**Решение:**
Перебираем центроид декомпозиции $C$.
1.  Случай 1: $C$ совпадает с центром тройки $A$. Нужно выбрать 3 вершины из разных поддеревьев на глубине $D/2$.
2.  Случай 2: Центр тройки $A$ находится в одном из поддеревьев относительно $C$.
    *   Это сводится к подсчету количества пар в *других* поддеревьях на определенной глубине.
    *   Используем технику слияния массивов подсчета («smaller to larger» merging) при пересчете глубин.
**Асимптотика:** $O(N \log^2 N)$ (добавляется логарифм из-за слияния или более сложной обработки).

## 3. Heavy-Light Decomposition (HLD)

Метод декомпозиции дерева на пути для обработки запросов (сумма на пути, изменение в точке и т.д.), обобщающий идеи дерева отрезков на деревья.

### Построение
1.  Для каждой вершины выбираем **тяжелое ребро** (heavy edge) — ребро, ведущее в ребенка с *максимальным* размером поддерева.
2.  Остальные ребра — **легкие** (light edges).
3.  **Тяжелые пути** (heavy paths) — цепочки тяжелых ребер.

### Свойства
*   Любой путь от корня до вершины содержит не более $\log N$ легких ребер.
*   Если двигаться по тяжелым путям, мы переключаемся между путями не более $O(\log N)$ раз.

### Применение
На каждом тяжелом пути строим структуру данных (обычно Дерево Отрезков — ДО).
Можно «выпрямить» дерево, записав все тяжелые пути подряд в один массив, и построить одно большое ДО над ним.

**Обработка запросов:**
1.  **Изменение в точке:** $O(\log N)$ (обновление в ДО).
2.  **Запрос на пути $(u, v)$:**
    *   Находим LCA (наименьшего общего предка).
    *   Разбиваем путь $u \to v$ на два: $u \to LCA$ и $v \to LCA$.
    *   Поднимаемся от вершины вверх по тяжелым путям. Каждый подъем обрабатываем как запрос к отрезку в ДО. Переход по легкому ребру — просто смена текущего пути.
    *   Так как смен путей $O(\log N)$, и запрос в ДО стоит $O(\log N)$, итоговая сложность: **$O(\log^2 N)$**.

## 4. Другие Задачи

### Задача О Пересечении Путей
Дано $Q$ путей. Найти количество вершин, которые принадлежат **всем** путям одновременно.

**Решение:**
1.  Рассматриваем пути как запросы прибавления $+1$ на пути в дереве.
2.  Используем HLD или другую технику для выполнения прибавлений.
3.  В Дереве Отрезков храним:
    *   Максимум на отрезке.
    *   Количество элементов, равных максимуму.
4.  Прибавляем $+1$ для всех $Q$ путей.
5.  Ответ: если глобальный максимум в дереве равен $Q$, то возвращаем «количество максимумов». Иначе 0.
6.  Асимптотика: $O(Q \log^2 N)$.

### Задача О $K$-й Порядковой Статистике На Пути
Найти $K$-е по величине число среди всех чисел, записанных на вершинах пути от $u$ до $v$.

**Решение (Персистентные деревья отрезков):**
*HLD здесь не обязательно.*
1.  Строим персистентное ДО. Версия $i$ соответствует пути от корня до вершины $i$.
2.  При переходе к ребенку добавляем значение в вершине в новую версию ДО.
3.  Запрос для пути $(u, v)$:
    *   Нам нужны значения на пути. Их количество можно выразить через суммы на путях от корня:
    *   $Count(x) = Count_{root \to u}(x) + Count_{root \to v}(x) - 2 \cdot Count_{root \to LCA}(x)$ (если значения на ребрах, иначе чуть сложнее с учетом вершины LCA).
4.  **Параллельный спуск:**
    *   Запускаем спуск одновременно по трем/четырем версиям ДО (версии для $u, v, LCA, parent(LCA)$).
    *   Смотрим, сколько чисел в левом поддереве (сумма $Left_u + Left_v - \dots$).
    *   Если сумма $\ge K$, идем влево. Иначе вычитаем сумму из $K$ и идем вправо.
5.  Асимптотика запроса: $O(\log N)$ (без лишних квадратов, так как спуск один).
