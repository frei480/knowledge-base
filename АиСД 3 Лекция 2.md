# Лекция 2: Алгоритм Ахо-Корасик

## 1. Постановка Задачи
**Дано:** Словарь из $N$ слов ($S_1, S_2, \dots, S_n$) и большой текст $T$.
**Задача:** Найти все вхождения всех словарных слов в текст $T$.

*Наивный подход:* Запустить префикс-функцию (КМП) для каждого слова отдельно. Это долго ($N$ проходов по тексту).
*Цель:* Решить задачу за один проход по тексту.

---

## 2. Бор (Trie)
Для эффективной работы со множеством слов используется структура данных **Бор**.

### Определение
**Бор** — это корневое дерево, где на рёбрах написаны буквы.
*   Из одной вершины не может выходить два ребра с одинаковой буквой.
*   Каждая вершина соответствует префиксу какого-то слова из словаря.
*   **Терминальная вершина** — вершина, в которой заканчивается полное словарное слово (помечается флагом `term = true`).

### Построение
1.  Начинаем с корня (пустая строка).
2.  Для каждого слова идем по символам.
3.  Если переход по букве есть — идем по нему.
4.  Если перехода нет — создаем новую вершину и ребро.
5.  В конце слова помечаем текущую вершину терминальной.

### Хранение Переходов (реализация)
В вершине нужно хранить, куда ведут переходы по буквам. Варианты:
1.  **Массив (`int next[SIGMA]`)**: Быстро ($O(1)$), но много памяти. Подходит для маленького алфавита.
2.  **Map (`std::map`)**: Экономит память, но медленнее ($O(\log \Sigma)$).
3.  **Hash Table (`std::unordered_map`)**: Экономит память, быстро в среднем ($O(1)$), но есть риск коллизий и оверхед.

> **Пример задачи на Бор:** Динамическое множество строк (добавить, удалить, проверить наличие). Бор позволяет делать всё это за время, пропорциональное длине строки запроса $O(|S|)$.

---

## 3. Алгоритм Ахо-Корасик
Идея: при чтении текста $T$ мы хотим всегда находиться в вершине Бора, соответствующей **самому длинному суффиксу** прочитанной части текста, который присутствует в Боре.

Для этого достраиваем Бор до автомата, вычисляя две величины для каждой вершины: **Суффиксную ссылку (`link`)** и **Функцию перехода (`step` / `go`)**.

### Суффиксная Ссылка (`link[v]`)
Это указатель на вершину, соответствующую **самому длинному собственному суффиксу** строки $v$, который также присутствует в Боре.
*   *Собственный суффикс* — суффикс, не равный самой строке.
*   Для корня `link` не определен (или ведет в фиктивный корень).
*   Для детей корня `link` ведет в корень (пустую строку).

### Функция Перехода (`step[v][c]`)
Показывает, в какую вершину мы попадем из $v$, если допишем символ $c$, стараясь сохранить максимально длинный суффикс, который есть в Боре.
*   Если в Боре есть прямое ребро $v \xrightarrow{c} u$, то `step[v][c] = u`.
*   Если ребра нет, то мы должны попробовать перейти по суффиксной ссылке и поискать переход там: `step[v][c] = step[link[v]][c]`.

### Построение (BFS)
Значения вычисляются по слоям (BFS), так как для вычисления значений вершины нужны уже посчитанные значения для вершин меньшей глубины (ее суффиксной ссылки и родителя).

1.  **База:** Для корня `link` не важен, `step[root][c]` равен либо ребенку (если есть), либо корню (если нет). Помещаем детей корня в очередь.
2.  **Шаг:** Извлекаем вершину $v$. Для каждого символа $c$ и ребенка $u$ (где $v \xrightarrow{c} u$):
    *   **Вычисление Link для ребенка:** `link[u] = step[link[v]][c]`.
        *(Логика: берем суффикс родителя и пытаемся продлить его символом $c$)*.
    *   **Вычисление Step для ребенка:** Если есть реальное ребро $u \xrightarrow{d} w$, то `step[u][d] = w`. Иначе `step[u][d] = step[link[u]][d]`.
    *   Добавляем ребенка в очередь.

### Асимптотика Построения
$O(V \cdot \Sigma)$, где $V$ — количество вершин в Боре, $\Sigma$ — размер алфавита.

## 4. Решение Задач С Помощью Ахо-Корасик

Мы идем по тексту $T$, поддерживая текущую вершину: `curr = step[curr][text[i]]`.

### Задача А: Найти Суммарное Количество Вхождений
Когда мы стоим в вершине `curr`, вхождениями являются все словарные слова, которые заканчиваются здесь. Это:
1.  Сама вершина `curr` (если она терминальная).
2.  Вершина `link[curr]` (если она терминальная).
3.  `link[link[curr]]` и так далее.

Чтобы не бегать по ссылкам каждый раз, используем ДП:
`cnt[v]` — количество терминальных вершин на пути по суффиксным ссылкам от $v$ до корня.
*   `cnt[v] = cnt[link[v]] + (1 if v is terminal else 0)`

**Алгоритм:**
Идем по тексту, при переходе добавляем к ответу `cnt[curr]`.
**Асимптотика:** $O(|T|)$.

### Задача Б: Напечатать Все Вхождения (позиции И слова)
Нам нужно вывести список всех слов, заканчивающихся в текущей позиции.
Проблема: Если просто идти по `link`, можно пройти много нетерминальных вершин (пустых суффиксов), что ухудшит асимптотику до квадратичной.

**Решение: Сжатая суффиксная ссылка (`compress` или `up`)**
`compress[v]` — ближайшая **терминальная** вершина, достижимая по суффиксным ссылкам из $v$.

**Вычисление:**
*   Если `link[v]` терминальная, то `compress[v] = link[v]`.
*   Иначе `compress[v] = compress[link[v]]`.

**Алгоритм:**
В каждой позиции текста прыгаем по `compress`: $v \to compress[v] \to compress[compress[v]] \dots$ и выводим эти слова, пока не упремся в корень.
**Асимптотика:** $O(|T| + \text{Answer})$, где Answer — суммарное количество найденных вхождений (оптимально, так как быстрее, чем просто вывести ответ, нельзя).

---

## Итог
1.  Строим Бор из слов словаря.
2.  BFS-ом вычисляем `link` и `step` (превращаем в автомат).
3.  Для оптимизации вывода/подсчета вычисляем `cnt` (кол-во терминалов) и `compress` (быстрая ссылка на терминал).
4.  Проходим по тексту, используя переходы автомата, и собираем ответы.
