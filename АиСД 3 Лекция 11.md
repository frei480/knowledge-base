# Лекция 11: Выпуклые Оболочки (Convex Hulls)

## 1. Определения

*   **Выпуклое множество:** Фигура называется выпуклой, если для любых двух точек $A$ и $B$ внутри фигуры отрезок $AB$ целиком принадлежит этой фигуре.
*   **Выпуклая оболочка (Convex Hull, $\text{conv}(S)$):**
    1.  Пересечение всех выпуклых фигур, содержащих множество $S$.
    2.  (Альтернативно) Минимальное по включению выпуклое множество, содержащее $S$.
    *   *Свойство:* Для конечного множества точек на плоскости выпуклая оболочка — это выпуклый многоугольник, вершины которого являются подмножеством исходных точек.

## 2. Лемма О Положении Точки Относительно Многоугольника
Пусть $P$ — выпуклый многоугольник, $A$ — точка вне вершин.
*   Если провести векторы из $A$ во все вершины $P$:
    *   Если они заметают угол $<\pi$, то $A$ лежит **вне** многоугольника.
    *   Если их нельзя заключить в угол $<\pi$ (они «смотрят во все стороны»), то $A$ лежит **внутри**.
*   Это позволяет построить алгоритм $O(N^2)$ добавления точки: если точка снаружи, проводим две касательные к старому многоугольнику и удаляем часть границы между ними.

## 3. Алгоритмы Построения (Статические)

### Алгоритм 1: Заворачивание Подарка (Jarvis March)
Идея: найти одну точно входящую точку и последовательно находить следующую сторону.
1.  Находим стартовую точку (самую нижнюю левую) — она точно на оболочке.
2.  Чтобы найти следующую вершину, перебираем все остальные точки и ищем ту, которая дает **минимальный полярный угол** (самый правый поворот) относительно текущей вершины.
3.  Повторяем, пока не вернемся в начало.
*   **Сложность:** $O(N \cdot H)$, где $H$ — количество вершин в оболочке.
*   **Применение:** Эффективен, если $H$ мало. Например, для случайных точек в нормальном распределении $H \approx \sqrt{\log N}$, тогда алгоритм работает очень быстро.

### Алгоритм 2: Сортировка По Углу (Graham Scan variant)
1.  Берем нижнюю левую точку $P_1$.
2.  Сортируем все остальные точки по полярному углу относительно $P_1$ (сравниваем через векторное произведение). Если углы равны, берем ближнюю (или дальнюю, зависит от реализации, лектор предлагает сначала ближние).
3.  Обходим точки в отсортированном порядке и поддерживаем стек вершин оболочки.
4.  Если новая точка образует с двумя верхними точками стека «неправильный» поворот (вогнутость), удаляем точки из стека (pop), пока выпуклость не восстановится.
5.  Добавляем новую точку.
*   **Сложность:** $O(N \log N)$ (из-за сортировки). Проход — линейный.

### Алгоритм 3: Сортировка По Координатам (Monotone Chain)
Более удобен для обобщения на динамический случай.
1.  Сортируем точки лексикографически (по $X$, затем по $Y$).
2.  Строим **верхнюю** (Upper) и **нижнюю** (Lower) оболочки отдельно.
3.  Для верхней: идем по точкам, поддерживаем выпуклость (удаляем последние, если поворот не туда).
4.  Для нижней: аналогично.
5.  Объединение дает полную оболочку.
*   **Сложность:** $O(N \log N)$.

## 4. Динамическая Выпуклая Оболочка
Задача: поддерживать $S$, добавлять точки (insert) и хранить $\text{conv}(S)$.

**Реализация:**
*   Храним отдельно Upper и Lower оболочки в `std::set`, упорядоченном по координате $X$.
*   **Проверка принадлежности:** Бинпоиском находим, между какими $X$ лежит новая точка, и проверяем, лежит ли она ниже/выше соответствующего отрезка оболочки. Если внутри — ничего не делаем.
*   **Добавление (если снаружи):**
    1.  Вставляем точку в `set`.
    2.  Рассматриваем соседей слева и справа. Если они нарушают выпуклость (оказываются «внутри» новой конфигурации), удаляем их из `set`. Повторяем удаление влево и вправо, пока выпуклость не восстановится.
*   **Сложность:** Амортизированно $O(\log N)$ на вставку.

## 5. Convex Hull Trick (CHT)
Метод оптимизации динамического программирования (DP).
*   **Задача:** Часто в DP формула перехода выглядит как $\max(DP[j] + \dots + A[i] \cdot B[j])$. Это можно интерпретировать как поиск максимума скалярного произведения вектора запроса с множеством векторов (точек), накопленных ранее.
*   **Геометрический смысл:** Максимум линейной функции на множестве точек достигается в вершине их выпуклой оболочки.
*   **Алгоритм:**
    1.  Храним точки $(B[j], DP[j] + \dots)$ в виде динамической выпуклой оболочки.
    2.  Для запроса с вектором $(A[i], 1)$ нужно найти вершину, максимизирующую скалярное произведение.
*   **Поиск максимума:**
    *   Функция скалярного произведения унимодальна вдоль сторон выпуклого многоугольника (сначала растет, потом убывает).
    *   Можно использовать **тернарный поиск** (если есть доступ по индексу) или **бинарный поиск** по производной (направлению роста).
    *   В общем случае (с деревом поиска): в каждой вершине дерева храним указатель на следующую точку оболочки. Сравниваем значения в текущей и следующей точке, чтобы понять, в какое поддерево спускаться.
*   **Сложность:** $O(\log N)$ на запрос.

### Частный Случай CHT
Если в задаче коэффициенты (например, $B[j]$ или $A[i]$) монотонны, можно не использовать полноценную динамическую оболочку с `set`, а использовать `deque` или `vector` и просто удалять/добавлять элементы с концов за $O(1)$ (амортизированно).
