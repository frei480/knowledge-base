## **2. Назначение И Цели разработки**
- 2.1. Назначение разработки
    Программное обеспечение предназначено для автоматизированной обработки набора списков объектов. Система должна выполнять слияние, агрегацию и вычитание данных на основе заданных правил эквивалентности, а также предоставлять гибкие возможности для сортировки, группировки и вывода результирующих данных.
    
- **2.2. Цели разработки**
    1. Разработать приложение на языке программирования C# с использованием платформы .NET.
    2. Реализовать алгоритм для идентификации эквивалентных объектов в множестве списков по заданным атрибутам.
    3. Реализовать механизм агрегации данных для дублирующихся объектов (суммирование числовых атрибутов).
    4. Реализовать логику формирования результирующих списков на основе операций над множествами (объединение и разность).
    5. Обеспечить возможность многоуровневой группировки и сортировки данных в полученных списках.
    6. Разработать механизм для консолидированного вывода всех обработанных списков в текстовом или табличном виде.

## **3. Требования К Программному обеспечению**
- **3.1. Функциональные требования**
    - **3.1.1. Входные данные**
        - На вход программе подается набор (множество) списков, содержащих объекты одного типа.
        - Объект представляет собой структуру данных с набором атрибутов (например, `Имя`, `Количество`, `Дата создания`, `Категория` и т.д.).
            
    - **3.1.2. Формирование основного списка эквивалентных записей**
        1. Система должна обрабатывать все исходные списки и формировать на их основе первый, "основной" список.
        2. Этот список должен состоять из уникальных объектов, которые считаются эквивалентными.
        3. **Правило эквивалентности:** Два объекта считаются эквивалентными, если у них совпадают значения ключевых атрибутов (например, атрибуты `Имя` и `Категория`). Конкретные атрибуты для сравнения должны быть легко настраиваемыми в коде.
        4. **Правило агрегации:** Если в исходных данных найдены эквивалентные объекты, в итоговом основном списке должен быть представлен один экземпляр этого объекта, а его числовой атрибут `Количество` должен быть равен сумме значений атрибута `Количество` всех найденных эквивалентных объектов.
            
    - **3.1.3. Формирование остаточных списков**
        1. Для каждого исходного списка должен быть сформирован свой "остаточный" список.
        2. Остаточный список формируется как результат операции разности множеств: `(Элементы исходного списка) - (Элементы, вошедшие в основной список)`.
        3. В остаточных списках не должно быть дубликатов. Если в исходном списке были дубликаты, не вошедшие в основной список, в остаточном списке они должны быть представлены в единственном экземпляре с просуммированным атрибутом `Количество`.
            
    - **3.1.4. Функциональность обработки списков**
        1. **Сортировка:** Каждый сгенерированный список (основной и все остаточные) должен поддерживать сортировку по любому из атрибутов объекта (по возрастанию и убыванию).
        2. **Группировка:**
            - Каждый список должен поддерживать группировку объектов по одному или нескольким атрибутам.
            - Поддерживается вложенная группировка с уровнем вложенности до 3.
            - При выводе каждая группа должна предваряться заголовком, идентифицирующим группу (например, "Категория: Электроника"). Для вложенных групп заголовок должен отражать всю иерархию (например, "Категория: Электроника, Производитель: Samsung").
                
    - **3.1.5. Вывод данных**
        - Все сгенерированные списки (основной и остаточные) должны быть объединены в один общий отчет.
        - Отчет должен выводиться в удобном для чтения формате: в виде простого текста с форматированием либо в виде таблицы (например, в консоли или текстовом файле).
        - При выводе должна быть четко видна структура: какой список выводится (основной или остаточный), а также соблюдена вся иерархия группировок с заголовками.
            
- **3.2. Нефункциональные требования**
    - **3.2.1. Требования к среде разработки и исполнения**
        - **Язык программирования:** C#.
        - **Платформа:** .NET (рекомендуется .NET 6 или новее для кроссплатформенности).
        - **Тип приложения:** Консольное приложение или настольное приложение (WPF/Windows Forms) для наглядной демонстрации.
            
    - **3.2.2. Ограничения и требования к производительности**
        
        - **Количество исходных списков:** не более 150.
        - **Максимальная длина каждого списка:** не более 1000 объектов.
        - **Максимальное количество атрибутов у одного объекта:** не более 10.
        - **Максимальный уровень вложенности группировок:** 3.
        - Приложение должно обрабатывать максимальный объем данных (150 списков по 1000 объектов) за приемлемое время (например, не более нескольких секунд).
