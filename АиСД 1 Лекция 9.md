# Лекция 9: Динамическое И Персистентное Дерево Отрезков

## 1. Динамическое Дерево Отрезков

### Мотивация
Обычное дерево отрезков (ДО) требует памяти $4N$. Если $N$ очень велико (например, $10^9$), но количество запросов $Q$ невелико, построить полное дерево невозможно. При этом часто массив изначально заполнен нулями.

**Идея:** Хранить только те вершины, которые реально нужны (в которых происходили изменения). Если мы никогда не спускались в поддерево вершины, её можно не создавать (считать, что там нули).

### Реализация
Вместо массива с индексацией `2*v` и `2*v+1` используется структура с указателями:
*   Создаем структуру `Node`: хранит сумму (`sum`), границы отрезка (опционально) и указатели на детей (`left`, `right`).
*   Изначально есть только корень, покрывающий диапазон $[0, N-1]$. Указатели на детей — `null` (или спецзначение), сумма — 0.

**Операции:**
1.  **Update (изменение в точке):**
    *   Спускаемся от корня к листу.
    *   Если нужно пойти в сына, которого нет — **создаем его** в этот момент.
    *   При возврате из рекурсии обновляем сумму в текущей вершине.
2.  **GetSum (сумма на отрезке):**
    *   Спускаемся как обычно.
    *   Если пытаемся пойти в несуществующую вершину — возвращаем 0 (так как в пустом поддереве сумма 0).

### Асимптотика
*   **Время:** $O(\log N)$ на запрос (высота дерева зависит от диапазона индексов).
*   **Память:** $O(Q \cdot \log N)$. Каждый запрос `update` создает не более $\log N$ новых вершин.
*   **Особенность:** Обработка происходит в **онлайне**.

## 2. Оффлайн-запросы И Сжатие Координат

Если все запросы известны заранее (оффлайн), можно сэкономить память и не писать динамическое ДО.

**Алгоритм:**
1.  Считать все запросы.
2.  Собрать все интересные координаты (индексы изменений и границы запросов суммы) в один список.
3.  Отсортировать список и удалить дубликаты.
4.  Каждой реальной координате сопоставить её порядковый номер в этом списке (0, 1, 2…).
5.  Построить **обычное** ДО на массиве размера $Q$ (количество уникальных точек).

**Обработка запросов:**
*   Для `update(pos, val)`: найти сжатый индекс для `pos` (бинарным поиском), обновить в ДО.
*   Для `get(L, R)`: бинпоиском найти ближайшие сжатые координаты, попадающие в отрезок, и сделать запрос в ДО.

**Асимптотика:** Время $O(Q \log Q)$, Память $O(Q)$.

## 3. Персистентные Структуры Данных

**Определение:** Структура данных называется *персистентной*, если она позволяет обращаться к своим предыдущим версиям.
*   **Частичная персистентность:** можно менять только последнюю версию, читать — любую.
*   **Полная персистентность:** можно менять и читать любую версию (ветвление истории).
*   В лекции рассматривается в основном частичная персистентность (линейная история версий).

### 3.1. Персистентный Массив
Задача: менять значение в точке, порождая новую версию массива. Узнавать значение `A[pos]` в версии `V`.

**Реализация:**
*   Вместо хранения $N$ копий массива, для каждого индекса `pos` храним историю его изменений.
*   `History[pos]` — это `vector<pair<version, value>>`.
*   **Update:** `push_back` новой пары (текущая версия, новое значение) в вектор соответствующего индекса.
*   **Get:** В векторе `History[pos]` бинарным поиском (upper_bound) ищем последнее изменение, версия которого $\le V$.

**Асимптотика:** Get — $O(\log Q)$, Update — $O(1)$ амортизировано. Память — $O(Q)$.

### 3.2. Персистентный Стек
Задача: иметь доступ к состоянию стека в любой момент времени.

**Реализация:**
*   Представляем стек как односвязный список (вершина ссылается на предыдущий элемент).
*   Храним массив `Head[v]` — указатель на вершину стека в версии `v`.
*   **Push(x):** Создаем новую ноду `x`, она ссылается на текущую `Head`. `Head[new_ver] = node_x`.
*   **Pop:** `Head[new_ver] = Head[old_ver]->next`.
*   **Revert:** Просто копируем указатель `Head` из нужной старой версии.

**Асимптотика:** $O(1)$ на все операции. Дерево версий образуется естественным образом.

## 4. Персистентное Дерево Отрезков (ПДО)

Основная идея: при обновлении данных не менять старые вершины, а создавать новые, **копируя путь**.

### Принцип Работы (Path Copying)
Пусть нужно изменить значение в листе.
1.  При спуске от корня к листу мы создаем копию текущей вершины.
2.  В новой вершине:
    *   Сын, в которого мы **не** идем, остается ссылкой на сына из старой версии (переиспользование поддеревьев).
    *   Сын, в которого мы идем, будет ссылкой на новую созданную копию.
3.  В итоге создается новая ветка длиной $\log N$, ведущая к новому листу. Остальная часть дерева общая с предыдущей версией.

### Хранение
*   Структура `Node` (сумма, `left`, `right`).
*   Массив `Roots[v]` — хранит указатель на корень дерева версии `v`.
*   `Roots[0]` — исходное дерево (или пустое).

### Асимптотика
*   **Update:** $O(\log N)$ времени и памяти (создается $\log N$ новых вершин).
*   **GetSum:** $O(\log N)$ времени. Нужно просто взять `Roots[v]` и сделать обычный спуск.

## 5. Применение ПДО: Задачи

### Задача 1: Количество Чисел На Отрезке $[L, R]$, Не Превосходящих $X$
(Ранее решалась через Merge Sort Tree за $O(\log^2 N)$).

**Решение через ПДО:**
1.  **Идея:** «Оживлять» элементы массива по очереди в порядке возрастания их значений.
2.  Сортируем исходный массив (пары `(значение, исходный_индекс)`).
3.  Изначально ДО заполнено нулями.
4.  Проходим по отсортированному массиву: для каждого элемента делаем `update` в его **исходной позиции** (добавляем +1).
5.  Сохраняем версию ДО после каждого добавления.
    *   Версия $k$ соответствует дереву, где единицами отмечены позиции $k$ самых маленьких чисел массива.
6.  **Запрос $(L, R, X)$:**
    *   Бинарным поиском по отсортированному массиву значений находим, сколько элементов $\le X$ (пусть это количество $cnt$).
    *   Берем версию дерева `Roots[cnt]`. В этом дереве «живы» только числа $\le X$.
    *   Делаем обычный запрос суммы на отрезке $[L, R]$ в этой версии.

**Сложность:** $O(N \log N)$ построение, $O(\log N)$ запрос.

### Задача 2: $K$-я Порядковая Статистика На Отрезке
Дано: неизменяемый массив. Запрос: найти $k$-е по величине число среди элементов $A[L \dots R]$.

**Решение (Параллельный спуск):**
1.  **Сжатие координат:** Пусть значения в массиве заменены на их ранги (от $1$ до $M$).
2.  **Построение:** Строим ПДО по **значениям** (индексы дерева от 1 до $M$).
    *   Версия $i$ дерева хранит частотный массив для префикса $A[0 \dots i]$.
    *   То есть `update` происходит в позицию `val = A[i]`.
3.  **Свойство:** Количество чисел со значением в диапазоне $[v_1, v_2]$ на отрезке массива $[L, R]$ равно:
    $$Count = \text{Sum}(Roots[R], v_1, v_2) - \text{Sum}(Roots[L-1], v_1, v_2)$$
    По сути, отрезок $[L, R]$ — это разность префиксов.

4.  **Алгоритм запроса (спуск):**
    Мы хотим найти такое значение, что на отрезке $[L, R]$ оно является $k$-м. Спускаемся одновременно по двум деревьям: `Roots[R]` и `Roots[L-1]`.
    *   Текущие узлы: $u$ (из $Roots[R]$) и $v$ (из $Roots[L-1]$).
    *   Считаем количество чисел в **левом** поддереве диапазона значений:
        $$cnt = u \to left \to sum - v \to left \to sum$$
        (с учетом проверки на null).
    *   **Если $cnt \ge k$:** Ответ лежит в левом поддереве (среди меньших значений). Идем влево в обоих деревьях.
    *   **Если $cnt < k$:** Ответ справа. Вычитаем $cnt$ из $k$ ($k = k - cnt$) и идем вправо в обоих деревьях.
    *   Когда дошли до листа — это и есть ответ (восстанавливаем значение, если сжимали координаты).

**Сложность:** $O(\log N)$ на запрос (без лишних бинпоисков). Это быстрее, чем Merge Sort Tree.
