Комбинация ранжирующих (оконных) функций, таких как `ROW_NUMBER()`, `RANK()`, `DENSE_RANK()`, и `NTILE()`, с оператором `CASE` — это мощный инструмент в арсенале любого SQL-аналитика. Он позволяет решать сложные задачи, связанные с условной логикой и сегментацией данных.

Давайте подробно разберем особенности их совместного применения на нескольких сценариях.

# Краткое Напоминание О Функциях

Для начала быстро вспомним, что делает каждая из основных ранжирующих функций. Представим, у нас есть таблица зарплат:

|   |   |
|---|---|
|**Имя**|**Зарплата**|
|Анна|100|
|Борис|120|
|Виктор|120|
|Галина|150|

Вот как сработают функции, упорядочивая по зарплате (`ORDER BY Зарплата DESC`):

|   |   |   |   |   |
|---|---|---|---|---|
|**Имя**|**Зарплата**|**ROW_NUMBER()**|**RANK()**|**DENSE_RANK()**|
|Галина|150|1|1|1|
|Борис|120|2|2|2|
|Виктор|120|3|2|2|
|Анна|100|4|4|3|

- `ROW_NUMBER()`: Уникальный номер для каждой строки.
- `RANK()`: Присваивает одинаковый ранг строкам с одинаковыми значениями, но оставляет "пропуски" в нумерации. (После двух человек с рангом 2 идет ранг 4).
- `DENSE_RANK()`: То же, что и `RANK`, но без "пропусков". (После двух человек с рангом 2 идет ранг 3).

# Особенности И Сценарии Применения С `CASE`

Существует два основных способа их совместного использования:

1. **`CASE` внутри `OVER()`**: Оператор `CASE` используется внутри клаузы `ORDER BY` или `PARTITION BY` самой ранжирующей функции для создания условной логики ранжирования.
2. **`CASE` для результата функции**: Оператор `CASE` применяется к результату, который вернула ранжирующая функция, для сегментации или присвоения меток.

Рассмотрим каждый подробно.

# Сценарий 1: `CASE` Внутри Клаузы `OVER()`

Это самый гибкий и мощный способ. Он позволяет менять сам _принцип_ ранжирования на лету.

Задача:

В компании есть таблица сотрудников employees с полями name, department, position, salary. Нужно пронумеровать сотрудников в каждом отделе по зарплате. Но есть особое условие: менеджеры (position = 'Manager') всегда должны идти первыми в списке своего отдела, а уже после них — все остальные, отсортированные по убыванию зарплаты.

Решение:

Здесь CASE идеально подходит для определения приоритета сортировки.

SQL

```
SELECT
    name,
    department,
    position,
    salary,
    ROW_NUMBER() OVER (
        PARTITION BY department
        ORDER BY
            CASE
                WHEN position = 'Manager' THEN 0
                ELSE 1
            END, -- Сначала менеджеры (им присвоен 0), потом остальные (им 1)
            salary DESC -- Внутри каждой группы (менеджеры/не менеджеры) сортируем по зарплате
    ) AS rank_in_department
FROM
    employees;
```

**Особенности этого подхода:**

- **Условная Сортировка:** Вы можете управлять порядком строк на основе любого сложного условия, а не просто по значению в столбце.
- **Гибкость:** `CASE` можно использовать и в `PARTITION BY`. Например, `PARTITION BY CASE WHEN department IN ('Sales', 'Marketing') THEN 'Commercial' ELSE department END` позволит объединить несколько отделов в одну группу для ранжирования.

**Пример результата:**

|   |   |   |   |   |
|---|---|---|---|---|
|**name**|**department**|**position**|**salary**|**rank_in_department**|
|Иван|Sales|Manager|150000|1|
|Мария|Sales|Specialist|120000|2|
|Петр|Sales|Specialist|110000|3|
|Елена|IT|Manager|200000|1|
|Сергей|IT|Developer|180000|2|
|Ольга|IT|Developer|180000|3|

Обратите внимание, что менеджеры Иван и Елена получили ранг `1` в своих отделах, даже если у них не самая высокая зарплата в отделе (как могло бы быть).

# Сценарий 2: `CASE` Для Обработки Результата Ранжирования

Это более распространенный сценарий. Сначала мы вычисляем ранг, а затем используем `CASE` для интерпретации этого ранга.

Ключевая особенность (и частая ошибка новичков):

Вы не можете использовать результат оконной функции в WHERE или CASE на том же уровне запроса, где она была вычислена. Это связано с логическим порядком выполнения операций в SQL: оконные функции вычисляются почти в самом конце, после WHERE и GROUP BY.

Поэтому **обязательно нужно использовать подзапрос или обобщенное табличное выражение (CTE)**.

Задача:

Разделить всех сотрудников компании на три категории на основе их общего рейтинга по зарплате:

- "Top 3": Первые три сотрудника с самой высокой зарплатой.
- "Top 10": Сотрудники с 4 по 10 место.
- "Standard": Все остальные.

**Решение с использованием CTE (рекомендуемый способ):**

SQL

```
WITH RankedEmployees AS (
    SELECT
        name,
        salary,
        DENSE_RANK() OVER (ORDER BY salary DESC) AS salary_rank -- Используем DENSE_RANK для корректной обработки "ничьих"
    FROM
        employees
)
SELECT
    name,
    salary,
    salary_rank,
    CASE
        WHEN salary_rank <= 3 THEN 'Top 3'
        WHEN salary_rank <= 10 THEN 'Top 10'
        ELSE 'Standard'
    END AS salary_category
FROM
    RankedEmployees
ORDER BY
    salary DESC;
```

**Особенности этого подхода:**

- **Сегментация:** Это классический способ для RFM-анализа, поиска "топ-N" записей, присвоения грейдов и т.д.
    
- **Читаемость:** Использование CTE (`WITH … AS …`) делает код намного чище и понятнее, чем вложенные подзапросы.
    
- **Недопустимость прямого использования:** Попытка написать так приведет к ошибке:

    SQL

    ```
    -- ЭТОТ КОД НЕ СРАБОТАЕТ!
    SELECT
        name,
        salary,
        CASE
            WHEN DENSE_RANK() OVER (ORDER BY salary DESC) <= 3 THEN 'Top 3'
            ELSE 'Standard'
        END AS salary_category
    FROM
        employees;
    ```

    Большинство СУБД не позволят использовать оконную функцию внутри `CASE` таким образом. Ее нужно сначала вычислить в подзапросе или CTE.

# Итоги И Ключевые Моменты

1. **Порядок выполнения SQL:** Всегда помните, что оконные функции вычисляются после `WHERE`. Чтобы отфильтровать или использовать результат ранжирования, поместите запрос с функцией в CTE или подзапрос.
2. **`CASE` в `ORDER BY` — для сложной логики:** Если вам нужно ранжировать по разным правилам для разных строк (например, "сначала VIP-клиенты, потом остальные"), используйте `CASE` внутри `OVER(…)`.
3. **`CASE` снаружи — для интерпретации:** Если вам нужно присвоить метки или категории на основе уже вычисленного ранга (например, "золотой", "серебряный", "бронзовый"), используйте CTE и применяйте `CASE` к столбцу с рангом во внешнем запросе.
4. **Выбор функции важен:** `ROW_NUMBER` даст уникальные номера, что полезно для удаления дубликатов. `DENSE_RANK` лучше подходит для рейтингов, где не должно быть пропусков.

Совместное использование этих инструментов открывает огромные возможности для аналитики данных прямо на уровне базы данных, делая запросы мощными и выразительными.
