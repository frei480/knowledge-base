Это классический пример, где для решения требуется многошаговая логика с использованием оконных функций. Простого `ROW_NUMBER()` здесь недостаточно, так как нужно одновременно вести два счета: один для "главных" ревизий (A, B, C...) и второй для "вложенных" (1, 2, 3...).

В вашем примере есть небольшая нестыковка в желаемом результате (например, и извещение `n-123123`, и документ `a-0002` имеют ревизию `B.1`). Я предположу, что логика должна быть следующей:

1. Каждая строка, где `document inventory number` **не пустой**, начинает новую **главную ревизию** (A, потом B, потом C и т.д.).
2. Все последующие строки (где `document inventory number` пустой) относятся к последней начатой главной ревизии.
3. Номер **вложенной ревизии** (1, 2, 3...) — это порядковый номер записи внутри одной главной ревизии.

Для решения этой задачи в MS SQL Server мы используем "трюк" с накопительной суммой для создания групп, а затем пронумеруем строки внутри этих групп.

### Пошаговое решение

**Шаг 1: Идентификация групп (главных ревизий)**

Мы можем создать "флаг" для каждой строки, где начинается новая главная ревизия.

CASE WHEN [document inventory number] IS NOT NULL THEN 1 ELSE 0 END

Затем, используя накопительную сумму (`SUM(...) OVER (...)`), мы можем присвоить уникальный номер каждой группе. Все строки от `a-0001` до `a-0002` получат групповой ID = 1, все строки от `a-0002` до `a-0003` получат ID = 2, и так далее.

**Шаг 2: Нумерация внутри групп**

Когда у нас есть ID группы, мы можем использовать `ROW_NUMBER()` с `PARTITION BY` по этому ID, чтобы получить вложенную нумерацию (1, 2, 3...).

**Шаг 3: Формирование строки ревизии**

- **Буква:** Мы можем получить букву из ID группы. Например, для ID=1 нужна 'A', для ID=2 — 'B'. В SQL Server для этого отлично подходит функция `CHAR()`, где `CHAR(65)` это 'A'. Значит, нам нужна формула `CHAR(64 + group_id)`.
- **Номер:** Это результат `ROW_NUMBER()` из Шага 2.
- **Конкатенация:** Соединяем букву, точку и номер.

### Итоговый SQL-запрос

Используем обобщенное табличное выражение (CTE) для чистоты и пошагового выполнения логики.

SQL

```
-- Для удобства создадим и заполним временную таблицу
DECLARE @DocumentHistory TABLE (
    [document inventory number] VARCHAR(50),
    [notice inventory number] VARCHAR(50),
    [denotation] VARCHAR(50),
    [date] DATE
);

INSERT INTO @DocumentHistory VALUES
('a-0001', null,     'xxx.010.000', '2021-02-23'),
(null,     'n-100121', 'xxx.010.000', '2021-02-25'),
(null,     'n-123123', 'xxx.010.000', '2021-03-23'),
('a-0002', null,     'xxx.010.000', '2021-04-15'),
(null,     'n-123456', 'xxx.010.000', '2022-02-03'),
('a-0003', null,     'xxx.010.000', '2023-03-03'), -- Изменен порядок для проверки логики
(null,     'n-466549', 'xxx.010.000', '2024-03-03'), -- Изменен порядок для проверки логики
(null,     'n-100699', 'xxx.010.000', '2025-02-03'),
(null,     'n-102346', 'xxx.010.000', '2025-03-12');


-- Основной запрос
WITH RevisionGroups AS (
    -- Шаг 1: Создаем группы с помощью накопительной суммы
    SELECT
        [document inventory number],
        [notice inventory number],
        [denotation],
        [date],
        SUM(CASE WHEN [document inventory number] IS NOT NULL THEN 1 ELSE 0 END) OVER (PARTITION BY [denotation] ORDER BY [date]) AS major_revision_group
    FROM
        @DocumentHistory
),
NumberedRows AS (
    -- Шаг 2: Нумеруем строки внутри каждой группы
    SELECT
        *,
        ROW_NUMBER() OVER (PARTITION BY [denotation], major_revision_group ORDER BY [date]) AS minor_revision_number
    FROM
        RevisionGroups
)
-- Шаг 3: Собираем финальный результат
SELECT
    [document inventory number],
    [notice inventory number],
    [denotation],
    [date],
    -- CHAR(64 + N) дает нам A, B, C... из 1, 2, 3...
    CHAR(64 + major_revision_group) + '.' + CAST(minor_revision_number AS VARCHAR(10)) AS revision
FROM
    NumberedRows
ORDER BY
    [date];
```

Для решения задачи по формированию столбца `revision` в формате `<буква>.<номер>` на основе истории изменений документа и уведомлений, можно использовать следующий подход в MS SQL:

```sql
WITH DataWithGroups AS (
    SELECT *,
        -- Группировка: новая группа начинается с каждого документа и каждого второго уведомления
        SUM(CASE 
            WHEN [document inventory number] IS NOT NULL THEN 1 
            WHEN [notice inventory number] IS NOT NULL AND 
                 LAG([notice inventory number]) OVER (ORDER BY date) IS NOT NULL THEN 1 
            ELSE 0 
        END) OVER (ORDER BY date ROWS UNBOUNDED PRECEDING) AS group_id
    FROM your_table
),
GroupedData AS (
    SELECT *,
        -- Буква группы (A, B, C...)
        CHAR(65 + (group_id - 1) AS group_letter,
        -- Нумерация внутри группы: документы всегда получают 1, уведомления - порядковый номер
        ROW_NUMBER() OVER (
            PARTITION BY group_id 
            ORDER BY CASE 
                WHEN [document inventory number] IS NOT NULL THEN 0 
                ELSE 1 
            END, date
        ) AS group_row_num
    FROM DataWithGroups
)
SELECT 
    [document inventory number],
    [notice inventory number],
    denotation,
    date,
    -- Формируем revision: буква группы + номер в группе
    CONCAT(
        group_letter, 
        '.', 
        CASE 
            WHEN [document inventory number] IS NOT NULL THEN 1
            ELSE group_row_num 
        END
    ) AS revision
FROM GroupedData;
```

### Объяснение решения:
1. **Группировка записей (DataWithGroups CTE)**:
   - Новая группа начинается:
     - С каждого документа (`[document inventory number] IS NOT NULL`)
     - С каждым вторым подряд уведомлением (когда текущее и предыдущее - уведомления)
   - `SUM() OVER` с условием инкремента группового идентификатора (`group_id`) реализует кумулятивное суммирование триггеров начала группы.

2. **Нумерация внутри группы (GroupedData CTE)**:
   - **Буква группы**: преобразуем `group_id` в буквы алфавита (65 = ASCII 'A').
   - **Порядковый номер в группе**:
     - Документы всегда получают приоритет (сортировка по `CASE...END` с `0` для документов).
     - Уведомления сортируются по дате.
     - `ROW_NUMBER()` назначает порядковый номер внутри группы.

3. **Формирование значения revision**:
   - Для документов: `<буква>.1`
   - Для уведомлений: `<буква>.<порядковый_номер>`
