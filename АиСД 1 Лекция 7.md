# Лекция 7: Стек, Очередь, Sparse Table

## 1. Завершение Темы Фибоначчиевы Кучи
Лектор заканчивает доказательство оценки времени работы из прошлой лекции.

*   **Утверждение:** Размер поддерева $S_k$ с корнем степени $k$ растет экспоненциально: $S_k \ge F_{k+2}$ (числа Фибоначчи).
*   **Следствие:** Так как $F_n \approx \phi^n$, то количество вершин $N$ связано со степенью корня логарифмически. Максимальная степень вершины $D(N) \approx \log_\phi N$.
*   **Вывод:** Операция `Consolidate` (уплотнение деревьев после `ExtractMin`) работает эффективно, так как количество деревьев после склейки будет порядка $O(\log N)$. Учетная стоимость всех операций — $O(1)$, кроме `ExtractMin`, которая работает за $O(\log N)$.

## 2. Стек (Stack)
**Определение:** Структура данных, работающая по принципу **LIFO** (Last In, First Out — последним вошел, первым вышел).
*   **Аналогия:** Стопка тарелок или стек вызовов функций в рекурсии.

**Основные операции:**
1.  `Push(x)` — добавить элемент в вершину.
2.  `Pop()` — удалить элемент с вершины.
3.  `Top()` — посмотреть значение элемента на вершине.

**Реализация:**
*   На основе **односвязного списка**.
*   Каждый элемент хранит значение и ссылку на предыдущий (нижний) элемент.
*   Все операции выполняются за **$O(1)$**.

### Задача 1: Правильная Скобочная Последовательность (ПСП)
**Задача:** Проверить, является ли строка правильной скобочной последовательностью (с разными типами скобок: `()`, `[]`, `{}`).

**Алгоритм:**
1.  Идем по строке слева направо.
2.  Если видим открывающую скобку — кладем ее в стек (`Push`).
3.  Если видим закрывающую:
    *   Проверяем вершину стека (`Top`).
    *   Если стек пуст или тип скобки на вершине не совпадает с текущей — **не ПСП**.
    *   Если совпадает — удаляем верхний элемент (`Pop`).
4.  В конце проверки стек должен быть пуст. Если что-то осталось — **не ПСП**.

**Корректность:** Доказывается через существование биекции (отображения) между открывающими и закрывающими скобками, при которой стрелки соответствия не пересекаются. Стек моделирует построение такой биекции.

### Задача 2: Обратная Польская Запись (ОПЗ)
**Определение:** Способ записи арифметических выражений, где оператор стоит *после* операндов (например, `3 4 +` вместо `3 + 4`). Скобки не требуются.

**Свойство однозначности:**
*   Для любого суффикса корректной ОПЗ «баланс» (кол-во чисел минус кол-во операций) $\le 0$, и только для всего выражения баланс равен 1. Это позволяет однозначно определить границы операндов.

**Вычисление значения выражения в ОПЗ:**
1.  Идем слева направо.
2.  Если число — кладем в стек (`Push`).
3.  Если операция (например, `+`):
    *   Достаем два верхних числа из стека (`Pop`, `Pop`).
    *   Применяем операцию.
    *   Результат кладем обратно в стек (`Push`).
4.  В конце в стеке останется ровно одно число — ответ.

## 3. Очередь (Queue)
**Определение:** Структура данных, работающая по принципу **FIFO** (First In, First Out — первым вошел, первым вышел).
*   **Аналогия:** Живая очередь в магазине. Добавление в конец, обслуживание с начала.

**Операции:**
1.  `Push(x)` — добавить в конец.
2.  `Pop()` — удалить из начала.
3.  `Front()` — посмотреть первый элемент.

**Реализация:**
*   На основе **двусвязного списка** (или односвязного с указателями на `head` и `tail`).
*   Все операции за **$O(1)$**.

## 4. Очередь С Поддержкой Минимума (Min-Queue)
**Задача:** Дан массив и скользящее окно длины $K$. Нужно найти минимум в каждом положении окна.
*   Обычная очередь не позволяет быстро искать минимум при удалении элемента.
*   Идея: реализовать очередь **на двух стеках**.

**Реализация очереди на двух стеках ($S_{in}$ и $S_{out}$):**
1.  **Добавление (`Push`):** Всегда кладем элемент в стек $S_{in}$.
2.  **Удаление (`Pop`):**
    *   Если стек $S_{out}$ не пуст, удаляем вершину $S_{out}$.
    *   Если $S_{out}$ пуст, перекладываем все элементы из $S_{in}$ в $S_{out}$ (при этом порядок элементов инвертируется, и первым на выход станет тот, кто первым пришел), затем делаем `Pop` из $S_{out}$.
3.  **Поддержка минимума:**
    *   В каждом стеке поддерживаем минимум (вместе со значением храним `min` среди всех элементов *ниже* него в этом стеке).
    *   Глобальный минимум очереди = `min(S_in.min, S_out.min)`.

**Асимптотика:**
*   Учетная стоимость (amortized complexity) всех операций — **$O(1)$**.
*   *Доказательство:* Каждый элемент проходит путь: Вход в $S_{in}$ $\to$ Выход из $S_{in}$ $\to$ Вход в $S_{out}$ $\to$ Выход из $S_{out}$. Максимум 4 операции на элемент.

## 5. Разреженная Таблица (Sparse Table)
**Задача (Static RMQ):** Дан неизменяемый массив. Нужно отвечать на запросы минимума на отрезке $[L, R]$.

**Идея:**
*   Предпосчитать минимумы для всех отрезков, длины которых являются степенями двойки ($1, 2, 4, 8, \dots$).
*   Обозначим $ST[i][k]$ — минимум на отрезке длиной $2^k$, начинающемся в индексе $i$.

**Построение (Precalc):**
*   Динамическое программирование: отрезок длиной $2^k$ состоит из двух отрезков длиной $2^{k-1}$.
*   Формула: $ST[i][k] = \min(ST[i][k-1], \ ST[i + 2^{k-1}][k-1])$.
*   Время построения: **$O(N \log N)$**.

**Ответ на запрос (Query):**
*   Любой отрезок $[L, R]$ длины $Len$ можно покрыть **двумя** пересекающимися отрезками длины $2^k$, где $2^k$ — максимальная степень двойки, не превосходящая $Len$.
*   Первый кусок: от $L$ длиной $2^k$.
*   Второй кусок: заканчивающийся в $R$ длиной $2^k$ (начинается в $R - 2^k + 1$).
*   Минимум на отрезке — это минимум из этих двух кусков (так как операция `min` идемпотентна, пересечение не портит результат).
*   Формула: $\text{Ans} = \min(ST[L][k], \ ST[R - 2^k + 1][k])$.
*   Степень $k$ ищется как $\lfloor \log_2(R - L + 1) \rfloor$ (можно предпосчитать логарифмы для всех длин за $O(N)$).

**Итог:**
*   Построение: **$O(N \log N)$**.
*   Запрос: **$O(1)$**.
