RAG против CAG: Устранение пробелов в знаниях в моделях искусственного интеллекта

00:00 Проблема знаний в языковых моделях

• Языковые модели не могут вспомнить информацию, отсутствующую в их обучающем наборе.
• Пример: премия "Оскар" 2025 года или история покупок клиента.
• Решение: методы дополненной генерации, такие как поиск информации.

00:34 Поисковая система дополненной генерации RAG

• Модель запрашивает внешнюю базу знаний для получения дополнительного контекста.
• Полученные документы передаются модели для обновления знаний.
• Обновленный контекст используется для генерации ответа.

01:18 Cache Augmented Generation CAG

• Вместо запроса базы знаний, CAG предварительно загружает всю базу знаний.
• Все знания помещаются в контекстное окно модели.
• Модель получает все доступные знания, а не только релевантные к запросу.

02:14 Сравнение RAG и CAG

• RAG: двухфазная система с автономной и онлайн-фазами.
• Автономная фаза: разбивка документов на фрагменты и создание векторных вложений.
• Онлайн-фаза: поиск по векторной базе данных и генерация ответа.

03:04 Процесс RAG

• Векторная база данных хранит вложения фрагментов документов.
• При запросе пользователя, RAG извлекает релевантные фрагменты и передает их модели.
• Модель использует вопрос и фрагменты для генерации ответа.

04:47 Преимущества RAG

• Модульность: возможность замены компонентов без перестройки системы.
• Возможность хранения больших объемов данных.

05:08 Процесс CAG

• Загрузка всех знаний в контекстное окно модели.
• Модель обрабатывает большие объемы данных за один проход.
• Кэширование внутреннего состояния модели для быстрого доступа к знаниям.

06:52 Различия между RAG и CAG

• RAG: извлечение только релевантных фрагментов по запросу.
• CAG: загрузка всех документов заранее и кэширование.
• Ограничения: размер контекстного окна модели в CAG.

07:28 Точность и задержка

• Точность RAG зависит от работы ретривера.
• CAG гарантирует наличие информации, но может добавлять несвязанную информацию.
• Задержка: RAG увеличивает время отклика из-за поиска информации.
• CAG минимизирует задержку благодаря кэшированию.

09:56 Масштабируемость

• RAG может масштабироваться до больших объемов данных.
• CAG имеет ограничения связанные с размером контекста модели.

13:04 Преимущества RAG

• База знаний огромна и динамична, постоянно добавляется новый контент.
• Кэширование всей информации превысило бы возможности моделей.
• RAG поддерживает точные ссылки на исходные материалы через поисковый механизм.
• Возможность постепенного обновления базы данных Vector для доступа к актуальной информации.

13:47 Система поддержки принятия клинических решений

• Врачи запрашивают истории болезни, руководства по лечению и информацию о взаимодействии лекарств.
• Ответы должны быть исчерпывающими и точными для консультаций с пациентами.
• Врачи часто задают сложные дополнительные вопросы.

14:16 Гибридный подход RAG и CAG

• RAG извлекает релевантное подмножество из огромной базы знаний.
• Извлеченные фрагменты передаются в модель с длинным контекстом, использующую CAG.
• Создается временная рабочая среда для конкретного случая с пациентом.

14:58 Сравнение RAG и CAG

• RAG эффективен для поиска в огромных базах знаний и предоставления ссылок.
• CAG предоставляет полный спектр медицинских знаний без повторного обращения к базе данных.
• RAG подходит для больших и часто обновляемых источников знаний, CAG — для фиксированных наборов знаний и быстрого развертывания.
• Выбор между RAG и CAG зависит от конкретных требований и ресурсов.
