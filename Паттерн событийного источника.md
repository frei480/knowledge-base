Stop Overwriting State And Use Event Sourcing Instead

00:00 Введение в паттерн событийного источника

• Проблема сохранения состояния: потеря истории изменений.
• Паттерн событийного источника сохраняет не конечное состояние, а каждое изменение.
• Примеры применения: банковская сфера, блокчейн, Git.

00:59 Создание базового примера событийного источника

• Определение типов событий: добавленный товар, удалённый товар.
```python
class EventType(StrEnum):
    ITEM_ADDED = "item_added"
    ITEM_REMOVED = "item_removed"
```

• Создание класса событий с неизменяемыми данными и временной меткой.
```python
@dataclass(frozen=True)
class Event[T = str]:
    type: EventType
    data: T
    timestamp: datetime = datetime.now()
```
• Настройка хранилища событий: список событий, методы добавления и получения событий.
```python
class EventStore[T]:
    def __init__(self):
        self._events: list[Event[T]] = []

    def append(self, event: Event[T]) -> None:
        self._events.append(event)

    def get_all_events(self) -> list[Event[T]]:
        return list(self._events)
```

    @cache
    def get_items(self) -> list[tuple[str, int]]:
        counts = Counter[str]()

17:41 Расширение модели инвентаря

• Введение класса данных Item с полями название, редкость и происхождение.
```python
@dataclass(frozen=True)
class Item:
    name: str
    rarity: str
    origin: str
```
• Универсализация класса событий и хранилища событий для поддержки различных типов данных.
• Необходимость изменения методов add_Item и remove_Item для работы с объектами Item.
```python
    @cache
    def get_items(self) -> list[tuple[str, int]]:
        counts = Counter[str]()
        for event in self.store.get_all_events():
            name = event.data.name
            if event.type == EventType.ITEM_ADDED:
                counts[name] += 1
            elif event.type == EventType.ITEM_REMOVED:
                counts[name] -= 1

        return [
            (name, count)
            for name, count in counts.items()
            if count > 0
        ]
	def remove_item(self, item: Item) -> None:
        if self.get_count(item.name) <= 0:
            raise ValueError(f"{item.name} not in inventory")
        self.store.append(Event(EventType.ITEM_REMOVED, item))
        self._invalidate_cache()
```
21:19 Прогнозы на основе событий

• Создание прогнозов «Самые популярные предметы» и «Происхождение предметов» на основе событий.
```python
def get_most_collected_items(events: list[Event[item]], top_n:int = 5)-> list[tuple[str,int]]:
	"""Returns a list of most frequently added item names."""
	counts = Counter[str]()
	for event in events:
		if event.type == EventType.ITEM_ADDED:
			counts[event.data.name] += 1
	return counts.most_common(top_n)
```
```python
def get_item_origins(events: list[Event[Event]]) -> dict[str,set[str]]:
	origins: dict[str,set[str]] = defaultdict(set)
	for event in events:
		if event.type == EventType.ITEM_ADDED:
			origins[event.data.name].add(event.data.origin)
	return dict(origins)
```
• Функции прогнозирования не меняют состояние, а анализируют его.
```python
events = store.get_all_events()
print("Most collected Items")
for name, count in get_most_collected_items(events):
	print(f"{name}: {count} collected")
```
• Возможность создания дополнительных прогнозов на основе редкости предметов, графиков по времени и по игрокам.

22:15 Преимущества и недостатки хранения событий

• Преимущества: полная история, аудит, отладка, восстановление состояния, разделение логики записи и чтения, мощная аналитика, неизменяемые данные.
• Недостатки: сложность запросов, необходимость переноса событий при изменении формата, не всегда необходимость.
• Рекомендации по использованию: для сложных и динамичных доменов, аналитики по времени, отладки.
